# Contributing

Thanks for your interest in contributing to this project! This document outlines the basics of setting up your development environment, our coding standards, and how to submit issues and pull requests.

## Getting Started

1. Fork the repository and clone your fork locally:

   ```bash
   git clone https://github.com/<your-username>/agent-test-repo.git
   cd agent-test-repo
   ```

2. Create a new branch for your change:

   ```bash
   git checkout -b my-feature-branch
   ```

3. Install any dependencies required by the project (see the project README for specifics).

## Coding Standards

- Write clear, self-documenting code and keep functions small and focused.
- Match the existing code style used in the file/module you're editing.
- Add or update tests for any behavior you add or change, where applicable.
- Keep commits focused and write descriptive commit messages.

## Submitting Issues

- Search existing issues before opening a new one to avoid duplicates.
- Provide a clear title and description, including steps to reproduce for bugs, and the expected vs. actual behavior.
- Include relevant environment details (OS, versions, etc.) when applicable.

## Submitting Pull Requests

1. Ensure your branch is up to date with `main` before opening a PR.
2. Reference any related issue(s) in the PR description (e.g. `Closes #123`).
3. Provide a clear summary of the change and the motivation behind it.
4. Make sure any relevant tests and checks pass before requesting review.

## Review Process

- A maintainer will review your pull request and may leave comments or request changes.
- Please respond to feedback and update your PR as needed.
- Once approved and checks pass, a maintainer will merge your pull request.

## Questions?

If you have questions, feel free to open an issue for discussion.
